# Asset Review Lab

The development-only `/?lab=assets` route reviews scenery, characters and equipment. It uses the shared native WebGPU pipeline, Golden lighting and FSR Temporal Quality / 0.50 defaults. It never edits scenes, removes assets or changes player saves.

## Review sessions

Run `npm run assets:review` from main to start or resume a dedicated private task workspace. Open its printed URL. `--browser` opens an owned automated native-WebGPU browser; without it the command starts a source server for manual use. Main's lab is read-only. `npm run agent:dev -- --lab assets --browser` supports inspection while implementing the lab in a regular task; Finish Review is restricted to dedicated review sessions.

Decisions save in order in the background to that workspace's [review records](../assets/asset-reviews.json). Pending saves are shown separately from saved decisions; Finish Review waits until all saves succeed. Pending decisions and notes survive a reload of the same tab, and closing or leaving with pending saves prompts a warning. A failed save retains the queue and offers Retry saving or an explicit discard of unsaved decisions. **Finish Review** commits only those records and runs the normal `agent:finish` local integration workflow. It never pushes. Success closes/cleans the completed session after displaying its result; failures preserve records and the worktree for retry. Other dirty paths, staged changes, unrelated commits or changed private exports block automatic handoff. Resolve real conflicts with an agent, then retry; never discard another task's work.

`npm run assets:review -- --task SLUG --finish` retries handoff without the browser. `--stop` closes only that session's preview, preserving decisions. Closing a tab does not integrate decisions. A stale tab cannot overwrite more recent records; retry retained pending decisions first, or explicitly discard them before Reload. Reload retains the selected appearance’s draft notes.

## Queue and Browse

Review Queue shows one base asset per family and prioritizes used unreviewed assets before unused candidates. Original library models take precedence, followed by original gallery models and standalone gameplay models. Material variants stay out of the list; usage includes the entire family. Approve, Deny and Mark for deletion advance immediately while saving in the background; Skip changes no decision and excludes the item only for the current session. Browse revisits any decision, with name/ID search and category, pack, status, usage and scene filters. Component meshes are hidden until explicitly enabled. Approve, Deny, Mark for deletion and Set unreviewed apply to the base asset and every variant, including variants prepared later. Mark for deletion records intent only. Older variant denials and deletion requests remain visible on the base asset until a new family decision supersedes them; existing notes and records are retained.

Compact browser panes keep the decision buttons in a fixed bar below the preview. Notes and usage expand above that bar; Escape closes them. Below 640 px, Assets opens the filter/list drawer without shrinking the preview. Wide panes retain three columns, with decisions above independently scrolling notes and usage.

Game View uses the canonical fixed orthographic gameplay camera, Camera Distance and normal graphics profile at real-world scale; it never fits or enlarges an asset to fill the frame. Orbit inspection, Fit and front/side/back views remain available for close review. Both use the shared native WebGPU/FSR Temporal pipeline, including AO, bloom, outlines and depth of field. Main’s lab reads and shares its saved graphics profile with private review ports; if no main profile has been shared, the current browser’s saved settings/defaults apply. Scene placement transforms, local lights and baked scene lighting are not reproduced in the isolated stage. A 1.8 m reference remains optional. Character motion samples are available when prepared and compatible; static viewing remains available if a sample fails. Approval requires a prepared, successfully displayed base asset. This is visual selection, not certification of collision, rig integration or gameplay animation.

As soon as an appearance is selected, the queue speculatively prepares its next two appearances. A prepared successor can display while its current fingerprint is rechecked; approval remains disabled until that check and display both succeed. Prepared models are capped at four entries and 512 MiB of estimated geometry/texture allocation; the selected asset may exceed this budget by itself, and large assets can reduce lookahead. File-identity checks invalidate metadata/fingerprint caches, and each actual selection rechecks its fingerprint before reusing prepared content. Approval still rejects changed art. Background writes retain revision checks so a stale tab cannot overwrite newer records. Failed preloads retry visibly when selected.

`npm run levels:measure -- --lab assets --reason "specific request or defect"` borrows the owned `agent:dev -- --lab assets --browser` preview and records four selection-to-visible samples without changing decisions. This measures queue latency, not FPS or whole-frame GPU cost. Existing review worktrees retain their source version; finish an old writable session and start a fresh session to pick up tool updates without discarding its decisions.

Usage is static ownership, not the current save or visible frame. It includes scenery placements, source/prepared fallbacks, fires, merchants, shelter stash, player/enemy models, potential player loadouts, enemy equipment, arrows and gathering tools. Expand each scene for placement IDs and roles. Build selection and dependency use are shown separately. Shared file aliases appear as dependents; cleanup must preserve those owners.

## Eligibility and changed art

| Decision | Scene eligibility |
| --- | --- |
| Unreviewed | Development audition only; explicit approval required for new integrated references and shipping |
| Approved | Base asset and variants are eligible while the base fingerprint matches and the required prepared inputs remain available |
| Denied | Retained for inspection, unavailable for scene use |
| Marked for deletion | Unavailable for use; separate cleanup work requested |

Assets without a decision start unreviewed. Ordinary development previews remain usable. `levels:check` rejects new unapproved uses relative to HEAD; the integration sanity gate compares against its actual main base. Existing debt is reported without blocking unrelated work. Staging any private content requires base approval covering every used appearance, conditional fallback and selected visual root; obsolete build selections must be removed or reviewed. Source-only builds with no private content retain structural/reference checks and cannot claim visual approval or playable-art readiness. `assets:review:check --shipping` always reports the complete approval gate, including unavailable private art.

The [shared adapters and usage resolver](../scripts/assets/review/index.mjs) are the authority for the lab and gates. Original library IDs, character source IDs and prepared variant slots retain identity across reexports. Base geometry, external material inputs, transitive catalog dependencies, the shared dry-highlight response and base display height enter approval fingerprints. Highlight-response changes require fresh approval even when model files are unchanged. A changed approved base becomes Unreviewed with its previous decision visible; variants inherit that result. Changing only a variant's material recipe does not require separate review. Variant inputs are still checked for availability before scene/build eligibility. Existing base approvals extend to variants; older explicit variant denials and deletion requests remain effective until a new base decision supersedes them. Legacy family denials remain visible and a new base decision replaces them. Approval never adds an asset to build selection.

Use `npm run assets:review:report` for JSON blockers, deletion requests, references, dependent IDs and completed exclusions. Family deletion requests expand to every active variant so cleanup cannot overlook them. `npm run assets:review:check` checks new uses against HEAD; pass `--base SHA` for another comparison or `--shipping` for all shipping blockers. Library lookup remains `npm run levels:find -- --query pine`.

## Separate deletion cleanup

Mark for deletion records intent only. An explicitly requested agent task uses the report, replaces/removes scene and gameplay references, repairs relevant collision/harvest/interaction ownership, removes obsolete build selections, and deletes only exclusive prepared outputs, thumbnails and catalog entries. Inspect all dependent assets and shared URLs first. Private licensed sources and source archives remain preserved. Unreviewed replacements may be auditioned, but require owner approval before new references integrate or ship.

After physical cleanup and reference validation, retain a small completed exclusion under `deleted` in `assets/asset-reviews.json`, keyed by the appearance ID, with `familyId`, the removed `url`, and `deletedAt`. Remove the completed decision from the pending deletion list. Exclusions suppress future imports/exports, including targeted character refreshes and bulk library imports; coverage treats these as intentional omissions. Restoring a deleted asset is explicit: remove the applicable exclusion in a reviewed task, prepare the output and review it anew. Nothing is automatically restored or approved.

Review metadata contains IDs, fingerprints and notes; licensed models, private catalog contents, captures and source paths remain ignored. Follow [asset preparation](ASSET_PREPARATION.md), [level authoring](LEVEL_DESIGN.md) and the [daily workflow](DEVELOPMENT.md).
