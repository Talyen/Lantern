# Architecture

Lantern keeps simulation and presentation explicit. This is a small prototype, not a general game engine.

## Owners and data flow

`src/levels/` owns typed area definitions, validation, seeded decoration and shared runtime construction. See [level design](LEVEL_DESIGN.md). Named area-change requests distinguish travel from appearance refresh; both prepare resources before commit. Area replacement releases its effects/instances and keeps renderer/shared asset caches; gameplay owns numeric boundaries, spawn/reset and gate state. Development-only authoring consumes this same runtime through a narrow automation bridge.


- `src/entry.ts` selects the development-only character gallery/animation comparison lab or normal play (starting midway along Forest Clearing’s approach). Legacy art/renderer URLs load the clearing without opening Options; Escape opens it.
- `src/gameplay/adventure.ts` owns continuing character progress, discovered campfires, versioned character save, per-session encounter/drop/chest snapshots and shared fire-safety decisions, cast clock and single return-portal link. `src/gameplay/inventory.ts` owns footprints, item instances, spatial placement, supply transfers and safe equipment displacement; `src/ui/adventure.ts` presents Inventory and Travel; `src/ui/loot.ts` projects name-only labels and selection; `src/rendering/adventure.ts` presents drops and portals without deciding their behavior.
- `src/gameplay/encounter.ts` owns plain numeric actor transforms (including ground height), 100-point health, per-enemy notice/pursuit/return state, contact clocks, cooldowns, interruptions and outcomes. It imports neither three.js nor browser globals.
- `src/clearing/clearing.ts` coordinates startup, simulation, pause gates, resets and the frame loop. `src/levels/builder.ts` owns area geometry, optional scenery and firelights; the graphics owner applies shared area lighting and atmosphere; `actors.ts` owns character instances, mixers, actions and timing. `input.ts` exposes movement, pointer aim, attack, dodge and menu requests; `camera.ts` owns follow, zoom, projection and inspection views.
- `src/rendering/frame-pacer.ts` gates clearing frames against the chosen FPS cap; elapsed simulation/animation time remains owned by the clearing loop.
- `assets/motion-profiles.json` owns stable Mixamo source IDs, trims and contact/release markers; `src/animation/combat-animations.ts` owns compatible weapon-profile selection and lazy clip loading. See [animation review](ANIMATIONS.md). Each actor has its own compatible catalog: Paladin J Nordstrom for the player and Goblin D Shareyko for the enemy. `assets/playable-characters.json` owns one authored model URL per actor, heights and compatible catalogs.
- `src/audio/` owns Web Audio playback, sound preferences and event-to-cue presentation. Encounter and Adventure expose numeric action/result events; animation replays never trigger sounds. The shared library remains read-only and optimized recordings are private under `public/vendor/audio/`. See [gameplay sound](AUDIO.md).
- `src/ui/hud.ts` presents animated health/mana orbs, recently damaged enemy health, results and asset errors. `options.ts` presents the Graphics and Sound dialog; rendering and audio settings owners parse and persist their respective preferences. See [graphics settings](GRAPHICS.md) and [gameplay sound](AUDIO.md). Gameplay loads coherent equipment motion profiles directly; motion selection belongs in the development comparison lab. UI invokes coordinator callbacks for input clearing and graphics updates; development authoring owns Restart and inspection controls.
- `src/rendering/renderer.ts` creates only a native WebGPU renderer and disables the pinned three.js internal fallback before initialization. `graphics.ts` applies settings, owns postprocessing and effects cleanup, and records frame measurements. `graphics-settings.ts` owns defaults and settings parsing. `area-lighting.ts` owns cached procedural PMREM skies and static irradiance probe preparation, using the globally bounded leased cache in `lighting-cache.ts`. `levels/lighting.ts` resolves the single Golden preset into one committed lighting definition for all consumers. Area transitions prepare lighting before commit; old lighting survives failed or superseded loads. Rendering receives scene and lighting references; it does not import UI or decide combat outcomes.
- `src/rendering/webgpu-pipeline.ts` owns the WebGPU render graph, scene/output dimensions and FSR reactivity. `fsr-temporal.ts` bridges the pinned FSR package to r186 pipeline callbacks and prepares its adapted accumulation shader (`fsr-accumulate.wgsl`) before startup. Converged stationary history survives current-phase clipping; motion, depth rejection, shading changes and reactivity restore clipping. FSR motion fades thin-feature locks and reduces accumulation from the package's 24-sample stationary limit to 8, with at least 1/8 current-frame contribution at full motion (0.5 render texels/frame). The package retains pass bindings, dispatch and resource ownership; integration or shader compilation failures stop startup with an actionable error. Pipeline preparation awaits the version-pinned fullscreen graph through renderer compilation before treating FSR as ready. `effects.ts` owns procedural effects and their resources.
- `src/assets/asset-library.ts` owns shared library resources and releasable instances. `src/labs/animations/animation-lab.ts` owns motion comparison using two instances of the same WebGPU pipeline, independent perspective cameras, native renderers and temporal histories, displayed side by side with linked orbit controls.
- `electron/main.cjs` serves the built renderer through the secure local lantern://app scheme with sandboxing, context isolation, and no Node integration. It supplies the initial display refresh rate for the default FPS cap.

Simulation operations mutate an explicitly owned encounter: create, reset, attack, and step. Updates return ordered animation, hit, label and outcome events. Presentation synchronizes transforms, then consumes events; rendering never decides health or victory. Player contacts resolve before movement and enemy attacks. Player input, movement and cooldowns advance once per frame; each authored enemy then advances its own AI. Clip durations remain inputs rather than render-owned clocks inside simulation.

Pausing, inspection, equipment loading and graph preparation stop simulation. The coordinator combines menu, inspection and preparation gates. Developer Restart resets encounter state, animation actions, effects and temporal history together. Camera follow preserves a fixed 35-degree downward pitch and 45-degree azimuth, with default zoom 1.35, and eases only its focus point. This is an ARPG-style approximation, not a verified camera specification from another game. Temporal sampling offsets are render-only; exactly one temporal resolve owns jitter, and the unjittered camera is restored before the next gameplay frame. Avoid moving runtime rules into a renderer or Options callback.

FSR keeps presentation at fixed pixel ratio 1 and reduces only scene buffers according to Resolution Quality. AO uses an independent opaque geometry pass and the native material `getAO` context hook, occluding indirect diffuse/specular light while preserving direct lighting and emission. The opaque FSR comparison uses that same AO context. AO precedes reconstruction. FSR sharpening is part of reconstruction; restrained DOF follows the resolved output with a jitter-corrected bilateral depth guide, followed by bloom, grading, ACES and one sRGB conversion. FSR uses a matched opaque-only pass and raw-color difference reactive mask; no scene visibility or materials are temporarily changed. Startup FSR failure produces an actionable error; runtime errors after successful rendering remain visible errors. Simulation remains independent of resolution quality.

Pointer coordinates stay in input; the coordinator reprojects them every active frame using the last displayed unjittered camera and the player's ground-height plane. Simulation receives an optional numeric aim point, applies facing after movement, and ignores points within 0.15 m. Pointer facing takes precedence over movement facing while free; attacks commit facing at acceptance, hit locks hold it, and dodges commit WASD direction or stationary pointer aim. Clearing input also clears aim, so menus and transitions require a fresh pointer event. Compatible forward/backward/strafe loops follow actual collision-resolved displacement relative to aim. Normalized gait phases align foot contacts; blocking uses directional walking legs beneath its shield pose.

Camera follow owns a ground-plane anchor with a 0.15 m radial dead zone and a separately eased height. Actual collision-resolved displacement produces 0.20 seconds of look-ahead, capped at 0.65 m; anchor and lead ease exponentially at 8 per second. Lead is suppressed inside the dead zone. Pointer turning never moves the camera. Restart, area arrival and inspection return reset follow state; pauses and fixed authoring views discard velocity samples without moving the view. The fixed offset remains owned by `src/clearing/projection.ts`.

`src/gameplay/movement.ts` owns navcat generation/path queries and Rapier grounded collision/line-of-sight behind a numeric simulation interface. Area data supplies explicit proxies and optional slope triangles plus stable harvestable trunk proxies, independent of asset availability. The coordinator replaces/disposes this adapter with the area and passes desired movement through it before presenting transforms.

`src/rendering/portal.ts` owns the generic gold/amber portal and bounded decal; the retained analytic swirl uses TSL through the existing graph. Portal effects pause with gameplay; portal destinations and lifetime belong to Adventure. See [library trials](LIBRARY_TRIALS.md).

Homestead is a safe area: movement remains active, enemies and combat outcomes are absent, and safe healing fires restore 3% maximum health per gameplay second within 3 m. Fires are blocked by a living enemy within 10 m or a pursuing/returning enemy anywhere in the area; Adventure applies the same rule to source interaction, travel commit and inactive destinations. Campfire menus pause simulation; a two-second Scroll of Return cast runs alongside combat and movement, with death taking precedence. Travel commits only after destination geometry/navigation loads, retaining player health and inactive enemy health/defeat plus ground drops. Entry clears transient attack actions rather than replaying attacks across scenes. A portal pair survives campfire travel and expires after returning through its home end, death or application restart. Death offers Return Home with collected scrolls retained.

Local character storage (`lantern.character.v1`) uses revision 4: individual item IDs, quantities, bag coordinates, equipped main/off slots, discovered fires, Woodcutting/Mining/Axe Combat XP, collected chest weapon claims, shelter restoration, stash contents and remaining Rested time. The 12 × 8 bag holds variable-size gear and multiple 99-unit supply stacks; equipped items use no bag cells. Revisions 1–3 migrate without discarding progress, including saved recovery entries for legacy quantities beyond capacity. Scroll/Wood totals and the type-based renderer loadout are derived, never separately saved. Invalid saves and failed storage operations retain visible recovery messages.

Adventure owns ground-drop identities, quantity, reachable landing position/height, 0.55-second landing clock and pickup target. Supplies collect within 1.5 m after landing only when a nearby physical route exists; equipment requires an explicit label/object click and never auto-equips. Pickup navigation has an independent path query, leaving enemy pursuit caches intact. Travel/death retain drops in area sessions; restart refreshes them. Dropped supplies wait for departure/re-entry before automatic recollection. The chest scatters its scrolls once per session and offers each unclaimed weapon; collection records permanent claims. Harvesting awards XP at contact and creates Wood drops.

Menus pause gameplay. Inventory rearrangement, splitting, packing and equipment displacement compute candidates first; asset/motion preparation completes before equipped-state changes commit. Dragging outside drops items onto reachable local ground. A Scroll of Return cast reserves one scroll against dropping until completion or death. The current raider still has a 50% one-scroll reward, player hits deal 50, and goblin hits deal 20. Broader economy, stats and enemy renewal remain later work.

## Rendering contract

Optional outlines are owned by `src/rendering/outlines.ts` within the shared graph. Mesh instances carry actor/prop strength; unregistered terrain, vegetation and effects default to zero. The environment surface family mapping selects solid scenery, and batching keys retain that classification. When enabled, an extra scene MRT attachment records strength with the beauty pass's cutouts, deformation and jitter. Soft inward mask/depth contours darken scene color before FSR, using the same depth and velocity without another geometry pass or temporal filter. FSR's raw opaque/translucent comparison stays unchanged. Off omits the active outline attachment and contour processing; the existing bounded graph cache may retain a recently used appearance. Toggle commits reset temporal history. Outlines default/reset to On and persist independently of other graphics choices.

All routes require native WebGPU. There is one visual pipeline in `src/rendering/webgpu-pipeline.ts`; gameplay, authoring and animation comparison use it. FSR Temporal is the sole reconstruction method, with Balanced and sharpening 0.50 as fresh/reset defaults. Output pixel ratio is always 1. SMAA/FXAA and the WebGL composer are removed. Unsupported native initialization stops startup with an actionable error; there is no backend substitution. The renderer's r186 `_getFallback` integration and backend compilation-error bridge must be revalidated on three.js upgrades. The bridge rejects shader failures that three.js otherwise logs while resolving `compileAsync`. Depth conversion supports orthographic and perspective cameras.

Legacy renderer URL parameters are ignored; retired rendering-method, render-scale and volumetric fields are ignored. Settings revision 6 retains the migration from old High/Low quality to independent shadow and particle presets, preserving applicable player preferences. CLI renderer overrides accept only the compatibility value `webgpu`. `scripts/check-rendering.mjs`, included in the handoff gate, prevents application WebGL support, legacy shader hooks, direct scene rendering and additional render-graph owners. Third-party packages may still contain unused backend code.

`src/rendering/surface-detail.ts` owns material-only 16× filtering, conservative resolution-derived mip bias and bounded POM sampling. Pipeline contexts supply per-graph bias and the compiled Texture Depth choice; cached On/Off graphs have independent uniforms/history. Geometry AO and irradiance preparation omit parallax; beauty and opaque FSR comparison share it. Material coordinates use physical surface gradients for orthographic/perspective cameras and preserve geometric depth/velocity/shadows. Loaded standard materials retain authored maps; prepared environment materials additionally bind owned opaque height/cavity/parallax-mask sidecars (spatial roughness remains in the embedded metallic-roughness map), recorded in lighting fingerprints and build dependencies. `woodland-ground.ts` owns coherent ground projections and normal/height-aware blending. Recipe and private-bake ownership stays in the environment manifest/exporter.

## Asset and resource ownership

The local [character gallery](CHARACTERS.md) owns roster comparison and per-rig sample previews under `src/labs/characters/`; private conversion and captures live in `scripts/assets/characters/`. It uses the shared WebGPU pipeline and never changes the playable actor.

Original texture studies are tracked; downloaded sources and vendor exports are ignored. Exporters read private sources under `.local/` and write only Lantern outputs. Mixamo is the sole animation provider. Library instances release their owned skeletons; the library owns cached shared textures/materials and is disposed after its instances. Renderer/effects owners retain their cleanup responsibilities.

Production builds stage explicitly selected Synty library entries plus dependency closure, authored playable models and complete per-rig motion catalogs, referenced area/environment art and file dependencies. Prepared lighting copies only indexed outputs. Development lab routes and gallery assets are excluded. This is a local-build convenience, not publication clearance. See [development](DEVELOPMENT.md) and [third-party notices](../THIRD_PARTY_NOTICES.md).

## Change method

Read the affected owner and consumers first. Preserve existing work; introduce dependencies or abstractions only for concrete consumers. Update this guide when ownership changes. Keep decisions beside their owner rather than only in an implementation plan. Extend the cheap simulation tests only for established behavior that merits ongoing protection.

## HUD and player controls

Health and mana use original text-prompted ImageGen frames under `assets/ui/orbs/`, with clipped animated red/blue liquid and smooth fill/drain transitions owned by `src/ui/orbs.css`. Gameplay owns health maxima and the currently unused 100-point mana resource. Enemy health appears above the enemy for three gameplay seconds after damage; projection uses the unjittered camera. Death, reset and travel clear its visibility.

Left click triggers a Basic attack or contextual gathering; loot clicks retain priority. Shift starts a 2.4 m dodge over 0.45 seconds with 0.25 seconds of invulnerability and a one-second cooldown. It uses the same collision and area boundary rules as walking, including safe areas and cleared encounters. Attack/hit locks block dodge; dodge blocks attack. Player-only Mixamo Dive Roll From Standing is trimmed from 1.25–3.55 source seconds and scaled to the dodge clock. The five base roles remain, with directional, block, chop and dodge roles supplied by compatible weapon profiles. Whole-canvas invulnerability flashing is removed; damage feedback stays local. Travel/reset clears transient dodge state. Hit sparks remain; weapon trails are removed.

B toggles Inventory; Escape closes the open menu or opens Options. Menus pause play, clear movement input, and dismiss on a click that begins and ends outside their panel, consuming that click. Fire shadows remain enabled; gameplay has no camera-following blanket fill. Settings revision 6 preserves applicable saved choices, including earlier sharpening values, while retaining the quality-preset migration. Fresh/reset sharpening is 0.50. Later player choices persist; comparison URLs remain temporary. DOF is a saved Off/Soft/Cinematic mode, with Cinematic as the fresh/reset default and old numeric values ignored. Fixed profiles belong to the shared WebGPU pipeline, which tracks camera-target focus and bypasses DOF when Off. Changing Soft/Cinematic updates uniforms; crossing Off rebuilds the graph. The character gallery explicitly disables DOF.

## Solo caster encounter

Forest Clearing contains the camp raider and a separate caster off the woodland approach. `layout.enemy` and optional `layout.caster` author their spawns; `Encounter.enemies` owns each actor's health, clocks, home, engagement and return state. Their notice areas are separated. Each enemy has its own collider, navigation route, compatible actor presentation, damage health bar and once-per-session scroll reward. Adventure preserves both states on travel/death; permanent character saves are unchanged. The camp chest names its guard and unlocks when that raider dies, independent of the caster. Fire safety evaluates every living enemy under the existing proximity/pursuit rules. The query-selected replacement encounter has been removed.

Encounter owns each enemy archetype and actor-specific projectile `owner`. The caster approaches within 6 m and visible ground, commits facing at cast acceptance, remains planted through windup/recovery, and releases one straight 8 m/s bolt at its compatible clip marker. Prepared Goblin casting is 1.6 seconds with release at 0.8 seconds; cooldown adds 0.5 seconds after the action. Hits interrupt windup through the existing reaction rule. Bolts use swept terrain/actor collision, consume on dodge contact, and use incoming direction for frontal shield damage reduction. Defeating an enemy clears only that enemy's bolts. A local victory leaves the distant fight available; the area is fully won only when all placed enemies are defeated. Pause freezes all cast/projectile clocks; travel clears transient actions and preserves enemy health/defeat.

`rendering/projectiles.ts` presents a cool pale-blue enemy bolt, compact charge and short release flash through node materials in the shared graph. Gameplay never reads visual lifetime. The caster uses its own staff profile while the camp guard retains the axe profile. Animation catalog loading uses rig identity separately from actor identity. Staff profiles explicitly name a compatible grip clip, baked to the actor's own rig.

## Equipment and trees

`gameplay/equipment.ts` owns item identity, hand occupancy and authored grips; `rendering/equipment.ts` stages releasable Synty instances on verified rig sockets. The coordinator prepares the model and compatible motions before committing, without resetting enemies or rewards; motion experimentation remains in the development animation lab. Axe/Sword may pair with a Shield; Bow/Staff occupy both slots. Empty hands disable weapon attacks. The clearing chest scatters Sword, Shield, Bow and Staff, with a permanent per-item claim on collection. Right mouse holds a frontal shield block with half movement speed and half damage in a 120-degree arc.

Encounter owns timed 12 m arrows/bolts and swept damage/terrain obstruction; `rendering/projectiles.ts` only presents those records. Input buffering holds one attack/dodge request for 150 ms and clears with menus, travel, death and reset. Safe and cleared areas retain basic attacks.

`levels/trees.ts` identifies standing trees before surface substitution; `levels/resources.ts` extends those stable IDs with authored mineral nodes and resource-level data. `gameplay/harvesting.ts` owns depletion, facing selection and the 120-second active-gameplay renewal clock, deferring occupied locations. The coordinator routes loot clicks before contextual gathering, checks nearby/pursuing threats, owns approach cancellation and synchronizes verified contact clocks. `rendering/gathering-tools.ts` temporarily hides combat attachments without changing the saved loadout. Builder preserves resource roots through batching; tree collision changes rebuild routes while depleted mineral cores remain solid. Standing geometry prepares lighting before depletion is reapplied, so gathering never triggers bakes.

`gameplay/skills.ts` owns derived gathering levels, yield/XP formulas, Rested tuning and the authored shelter recipe. Adventure awards harvested XP only for collected quantities through drop provenance; transferred or re-dropped materials cannot grant more. It also owns repair consumption, lossless paired inventory/stash transfers and active Rested time. `rendering/shelter.ts` presents the open timber-and-canvas cover; the prepared area appearance and repair consumption commit together. Inventory presents skill progress and Rested without rebuilding grids on each timer tick. See [gathering and shelter](GATHERING.md).

## Area lighting

Every route uses the shared Golden preset from `levels/lighting-preset.ts`; area definitions author only small overrides. Alternate presets, random moods, lighting URL switches and legacy full lighting definitions are removed. See [lighting authoring](LIGHTING.md). The resolver supplies `environment`, `probes`, `saturation`, `grade` and preset distance fog, deriving initial probe coverage from the playable boundary. Environment skies are original floating-point radiance independent of the backdrop, prefiltered once with native WebGPU PMREM. Static scenery is cloned into an isolated bake scene without actors, portals, particles or local animated lights. The native `LightProbeGrid` addon captures surface radiance from the sun and environment, adding local diffuse bounce without baking readability fill or hemisphere energy. This preparation uses the addon internally; gameplay and labs still use the single shared visual graph.

Preparation is serialized and suspends presentation while the renderer is capturing probes. Probe signatures include only resolved bake lighting, loaded geometry/instances/materials, source bytes, procedural surfaces and surface mode. Gameplay metadata does not invalidate GI. Commit attaches the prepared grid/environment only after area construction and travel checks succeed. Use renderer-wide LRU limits of eight skies / 32 MiB and eight probe appearances / 16 MiB; committed and candidate leases prevent premature disposal. Cancelled candidates release their leases. Prepared native atlases load by fingerprint, with live baking retained when prepared data is unavailable. Dispose cached resources with Graphics. Authoring changes rebake, unchanged revisits reuse the cache. Native PCF supplies sun and point-light shadows; grass receives scenery shadows without casting blades. Main sun shadows fit visible ground/raised scenery, snap their center to shadow texels, and use a bounded depth envelope including offscreen static casters. Shadowed fires use their point light directly; authored intensity survives graphics updates, with a small warmth multiplier and flicker.

The verified Paladin/Goblin legacy FBX material conversion clears imported untextured metalness: Blender maps Phong ReflectionFactor to Metallic, which incorrectly makes body skin/cloth conductive. Authored color, normal and specular textures survive. PBR GLB sources bypass this correction; the playable Paladin retains its original authored textures.

Environment palette, material treatment, the fixed Golden woodland baseline and local surface preparation follow [the art direction](ART_DIRECTION.md).

`player-lantern.ts` owns the optional personal lantern prototype, its privately loaded cage model, warm primary point light and short-range owner bounce. The coordinator stages area/surface changes, commits successful changes and toggles the personal light without rebuilding the area. The light attaches to the verified player rig and stays outside static scenery/probe preparation. Renderer disposal on page exit releases the native device along with lighting/effect resources.

Shadow and particle presets are owned by `src/rendering/quality-presets.ts`. Shadow map changes release old targets; quality never changes authored light count, coverage, bias or softness. Particle presets affect active capacity, continuous emission and weather rate, retaining combat burst timing/counts. Volumetric rendering and bounded mist regions are retired.

Graphics settings arrive as immutable snapshots. Ordinary values update once per presentation frame without resizing or clearing temporal history. Structural changes settle for 150 ms; closing Options flushes the latest request. The shared pipeline serializes candidate preparation, holds the last image while compiling, commits only the newest successful request and retains the working graph on failure. Resolution Quality resizes existing scene buffers; two recently used effect graphs are retained at most. Retired graphs release r186 render bindings for their own pass targets as well as node resources. Options remains HTML on the browser main thread; worker isolation is not implemented.
