# Architecture

Lantern keeps simulation and presentation explicit. This is a small prototype, not a general game engine.

## Owners and data flow

`src/levels/` owns typed area definitions, validation, seeded decoration and shared runtime construction. See [level design](LEVEL_DESIGN.md). Area replacement releases its effects/instances and keeps renderer/shared asset caches; gameplay owns numeric boundaries, spawn/reset and gate state. Development-only authoring consumes this same runtime through a narrow automation bridge.


- `src/entry.ts` selects the character gallery, animation comparison lab or normal play (starting midway along Forest Clearing’s approach). Legacy art/renderer URLs load the clearing without opening Options; Escape opens it.
- `src/gameplay/adventure.ts` owns the continuing scroll inventory, discovered campfires, versioned character save, per-session encounter/drop/chest snapshots and shared fire-safety decisions, cast clock and single return-portal link. `src/ui/adventure.ts` presents Inventory and Travel; `src/rendering/adventure.ts` presents drops and portals without deciding their behavior.
- `src/gameplay/encounter.ts` owns plain numeric actor transforms (including ground height), 100-point health, local notice/pursuit/return state, contact clocks, cooldowns, interruptions and outcomes. It imports neither three.js nor browser globals.
- `src/clearing/clearing.ts` coordinates startup, simulation, pause gates, resets and the frame loop. `src/levels/builder.ts` owns area geometry, optional scenery and firelights; the graphics owner applies shared area lighting and atmosphere; `actors.ts` owns character instances, mixers, actions and timing. `input.ts` exposes movement, pointer aim, attack, dodge and menu requests; `camera.ts` owns follow, zoom, projection and inspection views.
- `src/rendering/frame-pacer.ts` gates clearing frames against the chosen FPS cap; elapsed simulation/animation time remains owned by the clearing loop.
- `src/animation/combat-animations.ts` owns Mixamo catalog selection and lazy clip loading. Each actor has its own compatible catalog: Paladin J Nordstrom for the player and Goblin D Shareyko for the enemy. `assets/playable-characters.json` owns model URLs, heights and the default Paladin surface; authoring comparisons accept `?paladin=authored|iron-gold-crimson|iron-copper-teal|slate-bronze-blue|grim-gold|grim-crimson|dark-brass|silver-gold|ivory-gold`.
- `src/ui/hud.ts` presents animated health/mana orbs, recently damaged enemy health, results and asset errors. `options.ts` owns the dialog, graphics controls, saved preferences and method selection; `motion-options.ts` owns motion selection and loading feedback. UI invokes coordinator callbacks for input clearing, motion installation, reset and inspection.
- `src/rendering/renderer.ts` creates only a native WebGPU renderer and disables the pinned three.js internal fallback before initialization. `graphics.ts` applies settings, owns postprocessing and effects cleanup, and records frame measurements. `graphics-settings.ts` owns defaults and settings parsing. `area-lighting.ts` owns cached procedural PMREM skies and static irradiance probe preparation, using the globally bounded leased cache in `lighting-cache.ts`. `levels/lighting.ts` resolves shared profiles into one committed lighting definition for all consumers. Area transitions prepare lighting before commit; old lighting survives failed or superseded loads. Rendering receives scene and lighting references; it does not import UI or decide combat outcomes.
- `src/rendering/webgpu-pipeline.ts` owns the WebGPU render graph, scene/output dimensions and FSR reactivity. `fsr-temporal.ts` bridges the pinned FSR package to r186 pipeline callbacks and prepares its adapted accumulation shader (`fsr-accumulate.wgsl`) before startup. Converged stationary history survives current-phase clipping; motion, depth rejection, shading changes and reactivity restore clipping. FSR motion fades thin-feature locks and reduces accumulation from the package's 24-sample stationary limit to 8, with at least 1/8 current-frame contribution at full motion (0.5 render texels/frame). The package retains pass bindings, dispatch and resource ownership; integration or shader compilation failures stop startup with an actionable error. Pipeline preparation awaits the version-pinned fullscreen graph through renderer compilation before treating FSR as ready. `effects.ts` owns procedural effects and their resources.
- `src/assets/asset-library.ts` owns shared library resources and releasable instances. `src/labs/animations/animation-lab.ts` owns motion comparison using two instances of the same WebGPU pipeline, independent perspective cameras, native renderers and temporal histories, displayed side by side with linked orbit controls.
- `electron/main.cjs` serves the built renderer through the secure local lantern://app scheme with sandboxing, context isolation, and no Node integration. It supplies the initial display refresh rate for the default FPS cap.

Simulation operations mutate an explicitly owned encounter: create, reset, attack, and step. Updates return ordered animation, hit, label and outcome events. Presentation synchronizes transforms, then consumes events; rendering never decides health or victory. Player contacts resolve before movement and enemy attacks, matching the original encounter. Clip durations remain inputs rather than render-owned clocks inside simulation.

Pausing, inspection, motion loading and graph preparation stop simulation; UI decides when those gates apply. Developer Restart and motion changes reset encounter state, animation actions, effects and temporal history together. Camera follow preserves a fixed 35-degree downward pitch and 45-degree azimuth, with default zoom 1.35, and eases only its focus point. This is an ARPG-style approximation, not a verified camera specification from another game. Temporal sampling offsets are render-only; exactly one temporal resolve owns jitter, and the unjittered camera is restored before the next gameplay frame. Avoid moving runtime rules into a renderer or Options callback.

FSR keeps presentation at fixed pixel ratio 1 and reduces only scene buffers according to Resolution Quality. AO uses an independent opaque geometry pass and the native material `getAO` context hook, occluding indirect diffuse/specular light while preserving direct lighting and emission. The opaque FSR comparison uses that same AO context. AO precedes reconstruction. FSR sharpening is part of reconstruction; restrained DOF follows the resolved output with a jitter-corrected bilateral depth guide, followed by bloom, grading, ACES and one sRGB conversion. FSR uses a matched opaque-only pass and raw-color difference reactive mask; no scene visibility or materials are temporarily changed. Startup FSR failure produces an actionable error; runtime errors after successful rendering remain visible errors. Simulation remains independent of resolution quality.

Pointer coordinates stay in input; the coordinator reprojects them every active frame using the last displayed unjittered camera and the player's ground-height plane. Simulation receives an optional numeric aim point, applies facing after movement, and ignores points within 0.15 m. Pointer facing takes precedence over movement facing while free; attacks commit facing at acceptance, hit locks hold it, and dodges commit WASD direction or stationary pointer aim. Clearing input also clears aim, so menus and transitions require a fresh pointer event. Existing run clips remain in use for sideways/backward movement and may show foot sliding.

Camera follow owns a ground-plane anchor with a 0.15 m radial dead zone and a separately eased height. Actual collision-resolved displacement produces 0.20 seconds of look-ahead, capped at 0.65 m; anchor and lead ease exponentially at 8 per second. Lead is suppressed inside the dead zone. Pointer turning never moves the camera. Restart, area arrival and inspection return reset follow state; pauses and fixed authoring views discard velocity samples without moving the view. The fixed offset remains owned by `src/clearing/projection.ts`.

`src/gameplay/movement.ts` owns navcat generation/path queries and Rapier grounded collision/line-of-sight behind a numeric simulation interface. Area data supplies explicit proxies and optional slope triangles, independent of asset availability. The coordinator replaces/disposes this adapter with the area and passes desired movement through it before presenting transforms.

`src/rendering/portal.ts` owns the generic gold/amber portal and bounded decal; the retained analytic swirl uses TSL through the existing graph. Portal effects pause with gameplay; portal destinations and lifetime belong to Adventure. See [library trials](LIBRARY_TRIALS.md).

Homestead is a safe area: movement remains active, enemies and combat outcomes are absent, and safe healing fires restore 3% maximum health per gameplay second within 3 m. Fires are blocked by a living enemy within 10 m or a pursuing/returning enemy anywhere in the area; Adventure applies the same rule to source interaction, travel commit and inactive destinations. Campfire menus pause simulation; a two-second Scroll of Return cast runs alongside combat and movement, with death taking precedence. Travel commits only after destination geometry/navigation loads, retaining player health and inactive enemy health/defeat plus ground drops. Entry clears transient attack actions rather than replaying attacks across scenes. A portal pair survives campfire travel and expires after returning through its home end, death or application restart. Death offers Return Home with collected scrolls retained.

Local character storage (`lantern.character.v1`) persists scroll count and discovered fire IDs. New characters receive three scrolls; stacks cap at 99. A raider has a 50% chance to drop one scroll once per defeat, collected within 1.5 m if the stack has room. Invalid saves and failed storage operations report a visible recovery message; unknown fire IDs do not produce destinations. Application restart refreshes encounters and portals, starting at the clearing midpoint with full health. Both actors have 100 maximum health; player hits deal 50 and goblin hits deal 20. The camp chest grants two return scrolls after victory, retaining open/overflow state per session; application restart refreshes it. Enemy repopulation, equipment, gold and broader persistence remain later work.

## Rendering contract

All routes require native WebGPU. There is one visual pipeline in `src/rendering/webgpu-pipeline.ts`; gameplay, authoring and animation comparison use it. FSR Temporal is the sole reconstruction method, with Balanced and sharpening 0.50 as fresh/reset defaults. Output pixel ratio is always 1. SMAA/FXAA and the WebGL composer are removed. Unsupported native initialization stops startup with an actionable error; there is no backend substitution. The renderer's r186 `_getFallback` integration and backend compilation-error bridge must be revalidated on three.js upgrades. The bridge rejects shader failures that three.js otherwise logs while resolving `compileAsync`. Depth conversion supports orthographic and perspective cameras.

Legacy renderer URL parameters are ignored; retired rendering-method, render-scale and volumetric fields are ignored. Settings revision 5 retains the migration from old High/Low quality to independent shadow and particle presets, preserving applicable player preferences. CLI renderer overrides accept only the compatibility value `webgpu`. `scripts/check-rendering.mjs`, included in the handoff gate, prevents application WebGL support, legacy shader hooks, direct scene rendering and additional render-graph owners. Third-party packages may still contain unused backend code.

## Asset and resource ownership

The local [character gallery](CHARACTERS.md) owns roster comparison and per-rig sample previews under `src/labs/characters/`; private conversion and captures live in `scripts/assets/characters/`. It uses the shared WebGPU pipeline and never changes the playable actor.

Original texture studies are tracked; downloaded sources and vendor exports are ignored. Exporters read private sources under `.local/` and write only Lantern outputs. Mixamo is the sole animation provider. Library instances release their owned skeletons; the library owns cached shared textures/materials and is disposed after its instances. Renderer/effects owners retain their cleanup responsibilities.

Production builds stage explicitly selected Synty library entries plus dependency closure. Prepared lighting copies only indexed outputs; other vendor directories currently copy wholesale. This is a local-build convenience, not publication clearance. See [development](DEVELOPMENT.md) and [third-party notices](../THIRD_PARTY_NOTICES.md).

## Change method

Read the affected owner and consumers first. Preserve existing work; introduce dependencies or abstractions only for concrete consumers. Update this guide when ownership changes. Keep decisions beside their owner rather than only in an implementation plan. Extend the cheap simulation tests only for established behavior that merits ongoing protection.

## HUD and player controls

Health and mana use original text-prompted ImageGen frames under `assets/ui/orbs/`, with clipped animated red/blue liquid and smooth fill/drain transitions owned by `src/ui/orbs.css`. Gameplay owns health maxima and the currently unused 100-point mana resource. Enemy health appears above the enemy for three gameplay seconds after damage; projection uses the unjittered camera. Death, reset and travel clear its visibility.

Left click triggers one attack aimed at the pointer's ground position. Shift starts a 2.4 m dodge over 0.45 seconds with 0.25 seconds of invulnerability and a one-second cooldown. It uses the same collision and area boundary rules as walking, including safe areas and cleared encounters. Attack/hit locks block dodge; dodge blocks attack. Player-only embedded Mixamo Dive Roll is trimmed from 0.65–3.65 source seconds and scaled to the dodge clock. The five shared combat motion roles stay unchanged; swapping them preserves dodge. Travel/reset clears transient dodge state. Hit sparks remain; weapon trails are removed.

B toggles Inventory; Escape closes the open menu or opens Options. Menus pause play, clear movement input, and dismiss on a click that begins and ends outside their panel, consuming that click. Fire shadows remain enabled; gameplay has no camera-following blanket fill. Settings revision 5 preserves applicable saved choices, including earlier sharpening values, while retaining the quality-preset migration. Fresh/reset sharpening is 0.50. Later player choices persist; comparison URLs remain temporary. DOF is a saved Off/Soft/Cinematic mode, with Cinematic as the fresh/reset default and old numeric values ignored. Fixed profiles belong to the shared WebGPU pipeline, which tracks camera-target focus and bypasses DOF when Off. Changing Soft/Cinematic updates uniforms; crossing Off rebuilds the graph. The character gallery explicitly disables DOF.

## Area lighting

Area definitions select shared profiles with supported moods and optional overrides; complete legacy definitions remain supported. See [lighting authoring](LIGHTING.md). The resolver supplies `environment`, optional Studio `fill`, `probes`, `saturation`, `grade` and profile distance fog, deriving initial probe coverage from the playable boundary. Environment skies are original floating-point radiance independent of the backdrop, prefiltered once with native WebGPU PMREM. Static scenery is cloned into an isolated bake scene without actors, portals, particles or local animated lights. The native `LightProbeGrid` addon captures surface radiance from the sun and environment, adding local diffuse bounce without baking readability fill or hemisphere energy. This preparation uses the addon internally; gameplay and labs still use the single shared visual graph.

Preparation is serialized and suspends presentation while the renderer is capturing probes. Probe signatures include only resolved bake lighting, loaded geometry/instances/materials, source bytes, procedural surfaces and surface mode. Gameplay metadata does not invalidate GI. Commit attaches the prepared grid/environment only after area construction and travel checks succeed. Use renderer-wide LRU limits of eight skies / 32 MiB and eight probe appearances / 16 MiB; committed and candidate leases prevent premature disposal. Cancelled candidates release their leases. Prepared native atlases load by fingerprint, with live baking retained when prepared data is unavailable. Dispose cached resources with Graphics. Authoring changes rebake, unchanged revisits reuse the cache. Native PCF supplies sun and point-light shadows; grass receives scenery shadows without casting blades. Main sun shadows fit visible ground/raised scenery, snap their center to shadow texels, and use a bounded depth envelope including offscreen static casters. Shadowed fires use their point light directly; authored intensity survives graphics updates, with a small warmth multiplier and flicker.

The verified Paladin/Goblin legacy FBX material conversion clears imported untextured metalness: Blender maps Phong ReflectionFactor to Metallic, which incorrectly makes body skin/cloth conductive. Authored color, normal and specular textures survive. PBR GLB sources and projected Paladin metallic masks bypass this correction.

Environment palette, material treatment, golden/silver entry selection and local surface preparation follow [the art direction](ART_DIRECTION.md).

`player-lantern.ts` owns the optional personal lantern prototype, its privately loaded cage model and warm point light. The coordinator stages profile choices, commits successful changes and toggles the personal light without rebuilding the area. The light attaches to the verified player rig and stays outside static scenery/probe preparation. Renderer disposal on page exit releases the native device along with lighting/effect resources.

Shadow and particle presets are owned by `src/rendering/quality-presets.ts`. Shadow map changes release old targets; quality never changes authored light count, coverage, bias or softness. Particle presets affect active capacity, continuous emission and weather rate, retaining combat burst timing/counts. Volumetric rendering and bounded mist regions are retired.

Graphics settings arrive as immutable snapshots. Ordinary values update once per presentation frame without resizing or clearing temporal history. Structural changes settle for 150 ms; closing Options flushes the latest request. The shared pipeline serializes candidate preparation, holds the last image while compiling, commits only the newest successful request and retains the working graph on failure. Resolution Quality resizes existing scene buffers; two recently used effect graphs are retained at most. Retired graphs release r186 render bindings for their own pass targets as well as node resources. Options remains HTML on the browser main thread; worker isolation is not implemented.
